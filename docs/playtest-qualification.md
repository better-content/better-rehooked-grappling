## Shipped-source promise and acquisition

When ReHooked is loaded, `ModMain` registers six native `HookItem` variants and their `HookData` (`IntroHookContent`, `IntroHookProfile`): Soap on a Rope, Block and Tackle, Grapnel Bundle, Climbing Vine, Ratchet Reel and Angler's Gaff. They have bounded ordinary hook range/travel/pull relative to wooden/iron hooks. The server mixins add soap vertical-pull damping, vine foliage-dependent pull, ratchet 3-pull/2-hold cadence, a small grapnel solid-edge catch and gaff boat hook/boarding within 2.5 blocks. `HookEntityMixin` and `RehookedMobGrappling` additionally allow server-side mob targets (including bosses extending `Mob`) to be grappled and tugged without hit damage; removed/ineligible targets retract; ordinary block grapples should retain priority. `ReHookedConfig` exposes `rehooked.mobGrappling`, default true, disabled when ReHooked is absent. ReHooked is optional in `mods.toml` but required to deliver this gameplay; mixins are gated by `ModMixinPlugin`. This is source behavior, **not verified client gameplay**.

This repository has **no recipes, loot-table modifiers or source block registrations** for these items; models/translations are in `src/main/resources/assets/better_rehooked_grappling/`. The pack's `kubejs/server_scripts/utility/21_starter_hook_loot.js` is the intended six-prototype acquisition reference (mineshaft, dungeon, shipwreck supply, ruined portal, toolsmith and taiga-house chest tables, 5–7% per eligible table); its `Item.exists` check and item output currently refer to `better_compat_fixes:<name>`, **not** the `better_rehooked_grappling:<name>` registry IDs in this source. Do not claim this loot path actually awards these six items without a pack-level registered-ID and chest-loot check. The pack's `kubejs/server_scripts/utility/hooks_drones_gates.js` references `better_rehooked_grappling:soap_on_a_rope` as a component for the mechanically assembled `rehooked:iron_hook`; other native ReHooked tiers have assembly recipes there. `kubejs/config/hover_annotations.json` documents the prototype tooltips; `kubejs/config/crafting_policy.json` marks this mod's crafting support `full`, which alone does not establish a recipe or loot path. No new recipe/acquisition behavior is authorized by this inventory. No block acquisition is applicable to this repository; test any pack-level progression dependency separately.

## Dynamic Trees leaf-hit repair (2026-11-20; after the historical inventory)

`HookEntityMixin` now replaces ReHooked's block collision ray with one that uses the outline shape **only for leaves that have no hook-projectile collision shape**. The ray's first block hit is therefore the leaf itself when Dynamic Trees foliage lies ahead of a trunk; other blocks keep their original collision shapes. No new block, registry entry or world mutation is introduced. The source GameTest places a real `dynamictrees:oak_leaves` block before stone, checks that it is projectile-passable and has an outline, then asserts ReHooked enters `PULLING` with `getHitPos()` equal to that leaf. The native fixture loads pack-pinned Dynamic Trees 1.4.10 only at development runtime, not inside the staged mod JAR. The fixture's **disposable-world-only** datapack suppresses Dynamic Trees' malformed optional `guide` recipe (empty conditional entry); no shipped recipe or ERROR/FATAL gate is changed.

`./gradlew verifyFull stageRuntimeJar --offline --console=plain --max-workers=2` passed locally: 6/6 required native GameTests, JUnit and cold fixture guard; evidence is in `build/gametest/` and `build/test-results/`. An earlier native run completed 6/6 but correctly failed the ERROR/FATAL guard because the upstream guide recipe logged a parsing ERROR; it is not counted as passing. This proves the isolated source fixture only, not a pack-client shot, all DT addons, multiplayer synchronization, or release qualification of an installed pack JAR. The historical five-test inventory above describes the older source and is not a current count.
